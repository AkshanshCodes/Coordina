The authenticated app uses a compact SaaS shell with onboarding for new
accounts and active workspace context for returning users.

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Marketing landing page |
| `/login` | Authentication page |
| `/app` | Authenticated workspace console |
| `/docs` | Lightweight redirect to `VITE_DOCS_URL` |

## Workspace UX

- `/app` loads the user's workspaces.
- `/app/projects` loads projects for `coordina.activeWorkspaceId`.
- Project creation stays lightweight; board setup happens after opening a project.
- Project filters are backend-backed: active by default, archived and completed on demand.
- Accounts without a workspace see onboarding cards with create and join flows.
- Returning users get the persistent sidebar and topbar shell.
- Workspace switching reloads workspace-scoped project data.

## UI primitives

Workspace screens use shared shadcn-style primitives: `Card`, `Button`,
`Dialog`, `DropdownMenu`, `Input`, `Textarea`, `Badge`, `Skeleton`, `Field`,
and `Separator`.

## Board feature

`src/web/src/features/board` is split by reason for change:

```text
features/board/
  api/board-api.ts             HTTP calls only
  model/                       pure TypeScript, no React
    board-selectors.ts         filters, metrics, WIP alerts, card predicates
    board-updates.ts           immutable optimistic transforms
    card-draft.ts              card form rules: change detection, validation, labels
    board-format.ts            display helpers
    dates.ts, labels.ts        shared primitives
    planning-insights.ts       plan explanations and tags
  hooks/
    use-board-resource.ts      board, members, graph, dependency analysis loading
    use-board-mutations.ts     server mutations, optimistic updates, notices
    use-card-panel-form.ts     card side panel form
    use-dismissible-layer.ts   outside click / Escape for popovers
    use-board-filters.ts       search and filters
    use-project-board.ts       composition and UI state for ProjectBoard
  components/                  rendering only
```

Workflow state comes from each list's `taskStatus`. List titles are display text
only.

## Frontend architecture

The web application mirrors the API's feature-oriented structure with shared contracts and infrastructure:

```text
src/web/src
├── features      # Product areas and UI/state owned by those areas (board: api/, model/, hooks/, components/)
├── lib           # Shared utilities and the API client
└── types         # Shared API/domain contracts used across features


### Frontend flow

| Step | Behavior |
| --- | --- |
| Select workspace | Existing workspace context persists `coordina.activeWorkspaceId` |
| Open Projects | `/app/projects` loads active projects by default |
| Toggle filters | Archived/completed buttons call backend query parameters |
| Create project | Dialog posts name, description, key, icon, and color |
| Edit project | Dialog updates metadata/status through the workspace-scoped API |
| Archive/delete | Confirmation dialog calls archive or permanent-delete endpoint |
