## Graph engine benchmark

`make graph-engine-benchmark` builds deterministic sparse dependency graphs and
measures a full board analysis two ways: the six individual native calls the API
used to make, and the single `coordina_graph_analyze_board` call it makes now. It
also checks that both produce the same ranking and fails if they differ.
`make test` runs a smoke pass at 100 and 1,000 nodes. There is no timing
threshold, so a slow CI runner cannot fail the build.

Pass `sizes="100 500"` to choose graph sizes.

Median timings recorded on a development laptop (`-O2`). Use them for relative
comparison only:

| Nodes | Before: individual calls | After: individual calls | After: batch call |
| --- | --- | --- | --- |
| 100 | 0.62 ms | 0.47 ms | 0.14 ms |
| 1,000 | 8.1 ms | 5.1 ms | 0.82 ms |
| 10,000 | 188 ms | 61 ms | 31 ms |

The batch call builds the graph snapshot and topological order once and reuses
them. Transitive dependent counts use one backward pass over the topological
order with per-node bitsets, instead of a traversal per node. Graphs larger than
16,384 nodes fall back to traversal to bound memory.

## API test suites

| Suite | Command | What it exercises |
| --- | --- | --- |
| Fast | `make api-test-fast` | Endpoints and services over in-memory stores. Runs in about a second, no Docker needed. |
| PostgreSQL | `make api-test-postgres` | The same endpoints over the Postgres stores, with real EF Core migrations, constraints, and transactions. |

`make api-test` runs both.

The PostgreSQL suite needs Docker. It starts one `postgres:16` container per run
with Testcontainers, migrates a template database once, and gives each test its
own database cloned from that template. Each database is dropped after its test.
If Docker is unavailable, tests fail with a message starting
`PostgreSQL integration tests require Docker:`.

Fast-suite endpoint tests derive from `ApiTest` and drive the API through
`ApiTestClient` (`Api`). It registers users and builds common setup in one call
(`CreateWorkspaceAsync`, `AddMemberAsync`, `CreateProjectAsync`,
`CreateBoardAsync`, ...), and a failed setup request reports its method, URL,
status, and body. Response records in `tests/api/Support/ApiContracts.cs`
mirror the JSON the web client receives.

The fast suite also runs the architecture and convention rules listed in
`CONTRIBUTING.md`.

Put a test in the PostgreSQL suite when the in-memory stores cannot catch the
bug: migrations and data backfills, transactions and race conditions, unique or
check constraints, and tenant scoping in SQL queries. Test classes derive from
`PostgresApiTest`, which provides `Api`, `Database`, and `Factory`.

Run the full quality gate before merging:

```bash
make quality
```

## Manual smoke flow

1. Register or sign in at `/login`.
2. Open `/app`.
3. Create a workspace and confirm the owner role.
4. Open `/app/projects` and create a project.
5. Archive it and confirm it is hidden by default.
6. Enable archived projects and confirm the status badge appears.
7. Mark a project completed and confirm edits are blocked.
8. Generate an invitation code, sign in as another user, and redeem it once.
9. Confirm only workspace owners or project owners can edit and archive.
10. Confirm a non-member receives `404` for workspace and project details.
11. Open a board, move a card into the last list, and confirm it shows as completed.
12. Rename that list and confirm the board metrics do not change.
